# Telegram: профиль и возможности устройства

Клиент передаёт исходную строку `Telegram.WebApp.initData` в `POST /api/session`
после загрузки SDK. Сервер проверяет HMAC-SHA-256 с токеном бота, дату запуска
(не старше часа, допуск часов вперёд 30 секунд), уникальность параметров и структуру
пользователя. `initDataUnsafe`, присланный отдельно ID и username для авторизации
не используются. Непустые невалидные данные дают HTTP 401; гостевой профиль вместо
неудавшегося входа не создаётся.

## Настройка

В серверном `.env` нужен `TELEGRAM_BOT_TOKEN` от того бота, который открывает игру.
`npm run dev`, `npm run dev:api` и `npm start` читают локальный `.env`; файл
игнорируется Git и не включается в архив деплоя. Токен передаётся только Node.js. Его нельзя добавлять в `VITE_*`, фронтенд или URL.
Пустой параметр сохраняет гостевой режим разработки, но вход с Telegram initData
вернёт HTTP 503 с понятным сообщением о настройке сервера.

Приложение открывается через главное Mini App, кнопку меню бота, inline-кнопку
`web_app` или Mini App ссылку. Обычная ссылка на HTTPS-сайт сама по себе не
обеспечивает данные авторизации. У некоторых других способов запуска initData нет.

Выкладка через `npm run deploy` передаёт локальный `TELEGRAM_BOT_TOKEN` отдельно
по SSH, через стандартный ввод, и атомарно обновляет серверный `.env` с правами
`0600`. Токен не передаётся в аргументах команды и не включается в архив исходников.
Если локальный токен отсутствует, сохраняется существующая настройка сервера;
если токена нет с обеих сторон, выкладка останавливается до переключения приложения.
Перед изменением создаётся закрытая копия `.env.before-telegram`.
Затем применяется `deploy/telegram.compose.yaml` поверх серверного Compose,
чтобы контейнер приложения получил параметр из серверного `.env`.
Обычное развёртывание новым `compose.yaml` содержит этот параметр непосредственно.
Деплой не нужен для проверки тестами: тесты используют отдельную временную БД и
фиктивного бота. Этот документ и реализация сами по себе ничего не публикуют.

## Прогресс и сессии

`players.telegram_id` — уникальный `BIGINT`; имя и username хранятся для отображения.
Таблица `player_sessions` содержит хеши отдельных случайных сессий устройств.
Сессия одного устройства не отменяет сессии других устройств и истекает через
30 дней бездействия именно этого устройства.

Если Telegram-профиль ещё не существует, к нему привязывается текущий неистёкший
гостевой профиль: UUID, баланс, улучшения, открытые зоны, покупки и заезды остаются
на месте. Гостевой cookie заменяется новым, старый теряет доступ. Начатый заезд
можно завершить с новой сессией. Если гостевой сессии нет, создаётся новый профиль.

Если профиль с таким Telegram ID уже есть, открывается именно он. Другой гостевой
профиль сохраняется отдельно; балансы и прогресс автоматически не объединяются.
Профиль одного Telegram-аккаунта не может быть перепривязан к другому аккаунту.
Конкурентные первые входы одного пользователя сериализуются в транзакции.

Миграция `005_telegram_accounts.sql` переносит существующие гостевые сессии
с исходным сроком действия. Столбец `players.session_hash` пока оставлен для
совместимости: при привязке гостя он тоже заменяется хешем новой сессии, чтобы
повторный запуск миграции не восстанавливал доступ старому cookie.

## Вибрация и ориентация

Звук и вибрация используют один поток `game/feedback/RunFeedbackEvents.ts`.
Ящики и обычные зомби дают лёгкий отклик, тяжёлые зомби — средний, близкие взрывы
и жёсткие приземления — сильный. Из событий одного кадра выбирается самый сильный;
между откликами проходит минимум 180 мс. Прохождение этапа даёт сигнал успеха.
Малые приземления и уже учтённые столкновения повторных сигналов не создают.

Вибрация включается отдельно от звука в гараже и на паузе; настройка сохраняется
на устройстве. В фоне, при скрытом документе и без поддержки API сигналов нет.
Ошибки нативного API не прерывают заезд и сохранение результата. Настройки находятся
в `apps/web/src/configs/haptics.ts`.

Во время заезда на API 8.0+ ориентация фиксируется только после поворота устройства
горизонтально. В портрете приложение ждёт поворота и сохраняет прежнюю подсказку.
При выходе из заезда снимается только установленная нами блокировка. Физическое
срабатывание вибрации и блокировки нужно проверить в клиенте Telegram на телефоне;
автотесты проверяют вызовы адаптера и его поведение при отсутствии поддержки.
