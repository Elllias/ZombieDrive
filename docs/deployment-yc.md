# Запуск в Yandex Cloud

Тестовая ВМ: `deploy@178.154.250.113`, зона `ru-central1-d`.
Адрес игры: `https://178-154-250-113.sslip.io`.
Серверный каталог: `/opt/zombie-drive`.

## Состав

Compose запускает `db`, `app` и `proxy`. PostgreSQL 18 хранит данные в постоянном томе
`zombie-drive_postgres_data`; роль `zombie_app` владеет схемой, но не является суперпользователем.
Node.js 24 раздаёт клиент и API с одного origin. Caddy принимает 80/443 и получает сертификат.
API и PostgreSQL не публикуют порты на хост. Логи каждого сервиса ограничены тремя файлами по 10 МБ.

`Dockerfile` проверяет типы, ESLint, тесты на отдельном временном PostgreSQL и сборку клиента.
Тесты выполняются от пользователя `node`; постоянная серверная база недоступна при сборке.
В runtime отсутствуют тесты и devDependencies. Образы зафиксированы по digest.

## Первый запуск

1. Установить Docker Engine и Compose из официального репозитория Ubuntu:
   [инструкция Docker](https://docs.docker.com/engine/install/ubuntu/).
2. В группе безопасности ВМ разрешить TCP 80/443 с `0.0.0.0/0`, TCP 22 со своего адреса `/32`.
3. Загрузить проект в `/opt/zombie-drive`. Не передавать `.git`, `.local`, `node_modules`,
   `dist`, `.env`, `coverage` и резервные копии. Не применять `rsync --delete` к каталогу сервера.
4. Подготовить `.env` на сервере:

```sh
cd /opt/zombie-drive
umask 077
cp -n .env.production.example .env
chmod 600 .env
openssl rand -hex 32
openssl rand -hex 32
```

Два разных результата записать в `POSTGRES_PASSWORD` и `APP_DB_PASSWORD`.
Секреты хранить только на сервере. `APP_DB_PASSWORD` должен содержать ровно 64 шестнадцатеричных
символа: он входит в URL подключения. `APP_HOST` задаётся без `https://` и завершающего `/`.
В `.env` не передаётся `DATABASE_URL`: Compose собирает его для приложения.

Скрипт `deploy/init-database.sh` создаёт роль только при инициализации пустого тома.
Изменение `.env` у существующей базы не меняет её пароли; ротация требует `ALTER ROLE`.

5. Проверить конфигурацию, собрать и запустить:

```sh
sudo docker compose config --quiet
sudo docker compose up -d --build --wait --wait-timeout 120
sudo docker compose ps
curl --fail --max-time 15 https://178-154-250-113.sslip.io/api/health
```

Healthcheck `db` ждёт готовности TCP-сервера PostgreSQL, затем запускается `app`.
Миграции выполняются до открытия порта API. `proxy` стартует после готовности API.
Получение сертификата может продолжаться после завершения `compose up`; HTTPS проверить отдельно.
Не публиковать вывод `docker compose config` без `--quiet`: он содержит пароли.

## Проверки и управление

```sh
cd /opt/zombie-drive
sudo docker compose ps
sudo docker compose logs --tail 50 app
sudo docker compose logs --tail 50 proxy
df -h /
```

Проверить в браузере и Telegram: гостевую сессию, старт и завершение заезда, покупку,
повторное открытие и сохранение прогресса. Первый запуск использует новую серверную БД;
локальная `.local/postgres` не переносится. В Telegram прогресс привязан к Telegram ID; в браузере гостевой профиль зависит от cookie.

Перезапустить приложение без удаления данных:

```sh
sudo docker compose restart app
```

Сервисы используют `restart: unless-stopped`. Статус `unhealthy` сам по себе не перезапускает
контейнер; при нём проверить логи и доступность базы.

Остановить игру с сохранением томов:

```sh
sudo docker compose down
```

Не добавлять `--volumes` / `-v`: эти флаги удаляют постоянные данные.

## Резервная копия

На Mac сохранить копию вне ВМ, указав существующий путь к ключу:

```sh
umask 077
ssh -i ~/.ssh/zombie-drive-yc deploy@178.154.250.113 \
    'cd /opt/zombie-drive && sudo docker compose exec -T db pg_dump -U postgres -d zombie_drive -Fc' \
    > zombie-drive.dump
```

Проверить код завершения SSH и ненулевой размер файла. Сначала выгрузить копию перед
обновлением или удалением ВМ. Восстановление проверять в отдельной пустой базе,
используя `pg_restore --no-owner --no-acl`; рабочую базу для проверки не очищать.

## Обновление одной командой

Из локального проекта:

```sh
cd /path/to/zombie-drive
npm run deploy
```

Команда использует `deploy@178.154.250.113` и ключ `~/.ssh/zombie-drive-yc`.
Подключение к ВМ этим ключом должно уже работать; ключ хоста проверяется через `known_hosts`.
Docker на Mac не требуется. Настройки можно передать переменными:

```sh
DEPLOY_HOST=deploy@178.154.250.113 \
DEPLOY_KEY=~/.ssh/zombie-drive-yc \
DEPLOY_DIR=/opt/zombie-drive \
DEPLOY_URL=https://178-154-250-113.sslip.io \
npm run deploy
```

`scripts/deploy.sh` загружает архив исходников в `releases/<дата-время>/source.tar.gz` на ВМ.
Секретные `.env`, `.local`, `.git`, `node_modules` и локальная БД в архив не входят.
`deploy/remote.sh` собирает образ Docker с проверками TypeScript, ESLint, тестами на временном PostgreSQL
и production-сборкой. В build-стадии устанавливается Python 3 для тестов скрипта настройки Telegram;
в runtime-стадию он не переносится. Прежнее приложение работает до окончания этих проверок.

В новый образ добавляются прежние хешированные клиентские чанки для уже открытых вкладок.
Контрольные суммы аудио и доступность файлов проверяются от UID 1000 до активации.
После этого создаётся `before.dump`; команда копирует его на Mac в
`.local/deployment-backups/<дата-время>.dump` с правами `0600` и только затем обновляет `app`.

Активация использует `docker compose up -d --no-deps --no-build --wait` и проверяет публичный HTTPS healthcheck.
При ошибке запуска или healthcheck возвращается прежний образ приложения. База при откате не восстанавливается
из дампа: покупки и заезды, появившиеся во время сборки, сохраняются. Несовместимые миграции требуют отдельного плана.
После успешной активации новый `APP_IMAGE` записывается в серверный `.env` с сохранением остальных параметров.

Команда обновляет сервис `app`. Инфраструктурные настройки остаются в серверных `compose.yaml`, `Caddyfile` и `.env`.
Исходники каждого обновления находятся в `releases/<дата-время>/source`, лог сборки — `build.log`,
предыдущий образ — `previous-image`. Параллельные сборки блокируются через `flock`; устаревший релиз
не активируется поверх другого обновления. Старые образы сохраняются для отката.

## Telegram и завершение теста

В BotFather указать HTTPS-адрес как Main Mini App. Отдельный процесс бота не нужен.

Перед завершением теста сохранить копию БД вне ВМ. После удаления ВМ проверить и удалить
ненужные диски, снимки и зарезервированный публичный IP в YC: остановка ВМ не прекращает
оплату этих ресурсов. Удаление ВМ и томов выполнять отдельно, после сохранения нужных данных.

После распаковки с закрытым `umask` исходные файлы могут иметь права `600`. В runtime-стадии
Dockerfile копирование выполняется с `--chown=node:node`; дополнительные слои с ассетами тоже
должны оставлять их читаемыми для UID 1000. До переключения проверить импорты API и чтение
`dist/web` командой `docker run --rm --network none --entrypoint node <образ> ...`.
